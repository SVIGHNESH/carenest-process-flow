Decisions locked in v1.0

The four lines that prevent arguments

01 - Confirmation

Admin confirms every paid booking. Payment does not auto-confirm.

02 - SMS

SMS provider is MSG91 for OTP, admin alerts, nurse alerts, user updates.

03 - State

BLoC replaces Provider across the whole user app.

04 - Push

No device push in this version. SMS plus email plus in-app refresh. FCM later.

Signup and verification

No token until both channels verify

Register collects
Full name, phone number, email, password, confirm password. All required, phone 10 digits, password 8 or more characters, passwords match.
On submit
Backend creates the account in an unverified state and sends a 6-digit OTP to the email (Brevo) and a 6-digit OTP to the phone (MSG91). No login token is issued yet.
Verify Contact
Two OTP inputs, each with a 10-minute expiry countdown, a Resend button enabled after 60 seconds and limited to 5 sends per 10 minutes, and a verified tick once accepted. 5 wrong attempts locks that code; resend to get a new one.
Continue
Enabled only when both email and phone are verified. Backend returns the login token and the app enters Home.
Interrupted
Closing mid-way returns to Verify Contact on next email plus password login, not Home.
Forgot password
Enter email, OTP to email, enter OTP, set new password, back to Login.
State
unauthenticated to registering to awaitingVerification to authenticated(user), plus passwordResetInProgress.

Refund rule

Whenever a booking with a completed payment moves to rejected or cancelled, the backend calls Razorpay refund for the full amount and records razorpay_refund_id. Payment becomes refunded, or refund_failed with admins emailed to refund manually.

Admin flow

External dashboard, via API.

Five admin moves

Catalogue to decision to oversight

  1. 1. Create services and nurses

    Services: name, description, price per hour, active. Nurses: name, email, phone, temporary password; nurse must change it on first login.

  2. 2. Get pinged on payment

    Homepage feed gets Booking #123 needs confirmation from GET /admin/notifications. Every admin phone in ADMIN_ALERT_PHONES gets an SMS. Admin emails receive a summary.

  3. 3. Confirm or deny

    Open GET /bookings?status=awaiting_admin. Confirm with PATCH /bookings/{id}/confirm, keeping the chosen nurse or picking another free nurse. Deny with PATCH /bookings/{id}/deny plus reason. Backend refunds on deny.

  4. 4. Manage live bookings

    Cancel with refund, reassign the nurse, add notes. Feed items arrive when a nurse starts or completes a visit or a user cancels.

  5. 5. Review nurses

    View each nurse leave and worked days.

Nurse app flow

cn_nurse in six moves.

Access and schedule

Login first, availability second

  1. 1. Login

    With the email and temporary password the admin issued. Forced password reset on first login.

  2. 2. Schedule

    Mark leave days or working hours per day. Days with no entry count as available.

Visit loop

Assignment to completion

visits
  1. 3. Assignment ping

    On admin confirm, nurse receives SMS You have a new visit: booking #123… and an email with the same details. Booking appears in Home / My Bookings.

  2. 4. Booking detail

    Patient name, age, sex, condition, contact phone, address with map pin, time slot.

  3. 5. Start and complete

    Start visit sets in_progress, Complete visit sets completed. Each change goes to the admin feed and the user receives an SMS.

  4. 6. Cancelled

    If cancelled after assignment, the nurse gets an SMS and the booking leaves the active list.
